**FILAMENT // STUDIO** — инженерная веб-система управления складом филамента, учета технологического брака и автоматического расчета себестоимости 3D-печати с поддержкой клиентского парсинга бинарных и текстовых файлов нарезки (`.gx`, `.gcode`, `.3mf`, `.ufp`, `.g`).

🔗 **Рабочее приложение (Live Demo):** **[https://filament-studio.vercel.app/](https://filament-studio.vercel.app/)**

---

## О проекте

При активной 3D-печати (особенно в закрытых камерах и при печати техническими полимерами вроде PETG, ASA, TPU, PA) учет остатков пластика на катушках «на глаз» приводит к тому, что филамент заканчивается посреди многочасовой детали. 

**FILAMENT // STUDIO** решает эту задачу за счет прямого чтения файлов из слайсера и ведения облачного склада с мгновенной синхронизацией между ПК и смартфоном по уникальному ключу доступа без необходимости регистрации через почту или пароли.

## Ключевые возможности

### 1. Мультиформатный парсер файлов нарезки (Client-Side)
Вся обработка тяжелых файлов происходит локально в браузере пользователя через `ArrayBuffer`, `DataView` и `JSZip` за доли секунды (без загрузки гигабайтных файлов на сервер):
* **Бинарный формат `.gx` (FlashForge / Adventurer 5M):** разбор бинарного заголовка `xgcode 1.0`, чтение смещений (offsets), автоматическое извлечение зашитого внутрь бинарника **BMP-превью 3D-модели**, точного времени печати в секундах и длины экструзии в миллиметрах.
* **Контейнеры `.3mf` и `.ufp`:** распаковка ZIP-архива на лету в оперативной памяти, извлечение метаданных слайсинга (`slice_info.config` / встроенного `.gcode`) и рендера сборочного стола (`plate_1.png`).
* **Текстовые `.gcode` / `.g` / `.gco`:** извлечение комментариев телеметрии из **Orca Slicer, Bambu Studio, PrusaSlicer, Cura и FlashPrint** (вес в граммах, метраж прутка, высота слоя, тип полимера и встроенные Base64-миниатюры).

### 2. Облачная синхронизация по ключам `KA-****-****`
* **Демо-песочница:** открыта по умолчанию для мгновенного тестирования всех функций. Оснащена системой автоматической самоочистки (сброс к эталонным катушкам каждые 30 минут или при переполнении).
* **Персональные склады (`KA-****-****`):** в один клик генерируется криптографически уникальный ключ формата `KA-XXXX-XXXX`. По этому ключу пользователь получает изолированное рабочее пространство в облачной базе данных **Neon PostgreSQL**, доступное с любого устройства.

### 3. Складской и экономический контроль
* Расчет полной себестоимости детали с учетом цены конкретной катушки (руб/г) и амортизации/электроэнергии принтера (руб/ч).
* Автоматический подбор подходящей катушки на складе по типу материала, распознанному из файла слайсера.
* Защита от списания в минус, предупреждение о нехватке пластика на катушке (расчет точного дефицита в граммах).
* Быстрая корректировка веса (`-50`, `-10`, `+10`, `+50` г) и прямой ввод точного остатка при взвешивании катушки на весах.
* Раздельный учет успешной печати и технологического брака (`[БРАК]`) с возможностью отмены (возврата граммов на катушку) любой записи в журнале.

## Архитектура проекта

Проект построен по модульному принципу с разделением слоя данных, конфигурации, серверного API и клиентских модулей:

```text
filament-studio/
├── app.py                  # Flask REST API, валидация данных и маршрутизация
├── config.py               # Конфигурация СУБД, регулярные выражения и пресеты G-code
├── db.py                   # Слой абстракции БД (Neon PostgreSQL в облаке / SQLite3 локально)
├── static/
│   └── js/
│       ├── parser.js       # Бинарный и архивный парсер (.gx, .3mf, .ufp, .gcode)
│       └── app.js          # Управление состоянием склада, расчеты и авторизация KA-****-****
├── templates/
│   └── index.html          # Инженерный интерфейс в стиле Industrial Dark (Tailwind CSS)
├── vercel.json             # Конфигурация бессерверного деплоя Vercel
├── requirements.txt        # Зависимости Python
└── LICENSE                 # Лицензия MIT
```

## Технологический стек

* **Backend:** Python 3, Flask, Gunicorn
* **Database:** PostgreSQL (`psycopg2-binary`, облачный кластер Neon Serverless) / SQLite3 (автоматический фоллбэк для локальной разработки)
* **Frontend:** HTML5, Tailwind CSS, Vanilla JavaScript (`ArrayBuffer`, `DataView`, `TextDecoder`, `JSZip`)
* **Fonts:** Space Grotesk, JetBrains Mono
* **Deployment:** Vercel Serverless Functions

## Локальный запуск

1. **Клонируйте репозиторий:**
   ```bash
   git clone [https://github.com/kaplz/filament-studio.git](https://github.com/kaplz/filament-studio.git)
   cd filament-studio
   ```

2. **Создайте виртуальное окружение и установите зависимости:**
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. **Запустите сервер разработки:**
   ```bash
   python app.py
   ```
   При локальном запуске без переменной `DATABASE_URL` приложение автоматически инициализирует локальную базу SQLite в `/tmp/filament_studio_v4.db`. Откройте в браузере `http://127.0.0.1:5000`.
